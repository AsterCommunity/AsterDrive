# 资源处理预算

资源预算属于处理输入的模块，不依赖可选的 HTTP/IP 限流开关。拒绝必须发生在昂贵分配、数据库全量读取或目标对象发布之前；超限不能伪装成完整结果。

## 目录深度

`aster_drive_model::types::folder::MAX_FOLDER_DEPTH` 是目录支持边界的事实源。虚拟 workspace 根深度为 0，第一层真实目录为 1，最多支持 4096 层。

- 创建目录和相对路径物化，在 writer 事务与 workspace mutation guard 内验证最终深度。
- 移动、复制和恢复检查目标父目录深度与完整源子树高度之和。复制分批写入时重新验证目标，不能信任之前事务中的目录位置。
- 祖先读取必须完整到根，检测循环、缺失或不属于当前 workspace 的祖先；不能返回截断链继续鉴权。
- 同步目录树预算为相对操作根的 128 层，超出时按入口现有语义转后台或明确拒绝。它与 4096 层的绝对目录支持边界承担不同职责。
- 存量超深数据不能通过新建、移动或恢复进入不受支持的活动路径；后台删除仍须能分页清理，保留取消和拓扑去重。
- 分享树最多自动加载 8 个父级的子项，其他分支由手动展开加载。该数值不限制目录的实际支持深度。

跨数据库测试必须包含超过 MySQL 默认递归深度的祖先链；SQLite 的通过结果不能代替 PostgreSQL/MySQL。

## 对象复制暂存

`StorageCopyOptions` 由调用方传入已验证大小和临时根。上传完成使用会话持久化的声明大小，不能重新读取可变源的 metadata 后放大预算。

原生服务端复制仍由驱动负责。通用回退通过 Forge 的 `create_runtime_temp_dir_guard` 使用 `<temp_root>/_runtime/object-copy/<operation>/source`：

1. 使用独占创建的私有文件，逐块读取并严格校验源长度；探测到额外字节或提前 EOF 时停止。
2. 完整暂存通过后，将同一打开文件回卷并流式上传，内存不随对象大小增长。
3. 成功、错误和取消都释放 Forge guard；进程异常退出遗留物由既有 runtime 临时根清理处理。

该机制需要源大小对应的本地临时磁盘空间。写盘失败必须返回错误并清理暂存，不得退回整对象内存缓冲。不支持流式上传的驱动仅保留有界小对象回退，大对象需要该驱动提供流式或原生复制能力。

## 第三方解析器

ZIP 使用精确锁定版本的逐条中央目录 API，在扫描前检查原始条目数，并对元数据读取、操作次数、deadline 和 ZIP64 扩展记录施加预算。升级依赖时必须保留构造期分配回归测试。

输入字节数、`spawn_blocking` 和超时不能约束压缩数据的解压输出分配。Lofty 0.25.5 压缩 ID3 帧仍缺少公开输出预算；此项尚未完成，不能将图片、ZIP 或 I/O 预算的验证结果扩大为音频解析已安全。
