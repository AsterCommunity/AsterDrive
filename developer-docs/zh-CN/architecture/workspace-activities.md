# 工作空间活动与文件归属

`files` / `folders` 的创建者保持不变，`modified_by_user_id`、`modified_by_username` 和 `modified_at` 表示最近一次成功的业务修改。`updated_at` 继续承担现有技术更新时间职责；后台存储维护不能覆盖业务归属。新资源以创建者初始化修改摘要，升级前资源保持未知，不根据创建者、当前修订或旧审计猜测修改人。

## 升级边界

必需活动和修改摘要的完整写入保证从新版本接管写入后开始。多主部署应统一升级所有可写 Primary 及执行 WebDAV、WOPI、后台任务的进程；旧版本写入者仍会绕过新字段和活动表。升级不根据旧审计或版本作者伪造未记录的历史。

## 写入边界

Drive 的 `workspace::activity` 服务与调用者共享数据库事务。名称、位置、内容、版本恢复、标签、图标、自定义属性及删除/恢复写入成功事实和修改摘要；失败、回滚及无变化操作不生成成功活动。共享存储、REST、WebDAV、WOPI 和目录树任务从已锁定资源取得前态，提交后发布存储通知。父目录不因子项变化递归更新修改人。读取、下载、锁与分享权限采用各自的审计策略，不覆盖资源修改摘要。

`workspace_activities` 保存事件 ID、操作关联 ID、事件发生时的 workspace、资源名称、actor 名称快照和动作详情。没有指向用户或资源的级联外键，账号/资源删除不抹掉历史。当前摘要不依赖活动保留。活动 ID 是分页顺序，同一资源通过业务锁串行记录；不能用时间戳或不同资源的 ID 推断数据库全局提交顺序。

`audit_logs` 继续承载系统、安全和管理审计。新文件业务修改在活动表形成唯一成功事实，audit manager 不再重复生成同类成功修改记录；旧审计保留历史含义，不伪装成升级后的活动。现有审计缓冲、flush、失败恢复与关停机制保持原契约。后台概览同时读取审计与业务活动统计，上传与显式内容编辑保留不同动作语义。跨数据库迁移 CLI 包含活动表。

后台日报的 `deletions` 是删除操作次数：同一天内共享 `operation_id` 的文件与目录删除只计一次，包括目录树后代和批量选择；新批量请求的 `audit_logs` 汇总携带对应活动关联 ID，不再额外增加删除次数。升级前没有关联信息的审计继续保留原计数语义。审计配置的默认动作、schema 选项、旧配置展示均排除必记文件活动动作，新写入显式拒绝此类动作；运行时不把升级前保存的旧动作集合当成非法配置扩大记录范围。

## 查询与披露

成员按现有资源权限读取文件/目录活动；团队全量活动及导出限 owner/admin，系统管理员使用独立管理路由。资源历史同时过滤 workspace 与资源 ID，不能随当前位置跨空间泄露历史。跨空间复制为源和目标分别追加同 operation ID 的活动，各侧只保存自身资源信息和 external 标记；目标空间不能查询源资源历史。复制不改源资源的修改摘要，批量与目录树复制共享操作关联 ID。公开分享不提供活动接口，公开列表去除创建者和修改者信息。

当前详情、目录与搜索列表批量读取可展示名称，活跃账号优先显示资料显示名，再回退用户名；删除账号回退资源内的用户名快照。活动保留发生时快照，不随当前显示名变化。API 不包含邮箱、头像凭据或用户管理信息。

文件详情默认只读取当前归属摘要；用户显式展开“文件活动”后才请求活动首屏。资源活动使用 `before_id` keyset 分页，前端按页替换已渲染记录并可前后翻页，不把整个历史累积到浏览器内存；关闭详情或切换资源会取消未完成请求。同一资源的列表刷新不重置活动页。列表/搜索的归属解析只投影公共用户名和显示名字段，并按批次查询。

团队管理页和系统团队管理页分别展示文件活动及团队管理审计，独立分页与导出，避免把两组已经分页的数据拼接成错误的统一时间线。原团队审计接口及 CSV 格式继续兼容。活动采用 `before_id` 游标，单页 1–200 条；CSV 固定最大 ID 边界、有行数上限及公式中和，流中途缺失记录时返回错误而不是报告完整导出。

`workspace_activity_retention_days` 默认 0（无限保留），独立于 `audit_log_enabled`、动作过滤和 audit 保留期。正数只清理过期活动，不改资源归属。该表提供持久业务历史，不宣称防管理员篡改或不可抵赖。

批量移动、复制、删除和目录树任务会复用已锁定的资源快照，按最多 200 条活动投影分批更新修改摘要并批量插入活动；不会为每个资源重复查询路径、单独更新归属或单独插入活动。活动详情仍逐资源保存，便于权限过滤和资源历史查询。CSV 导出按固定 ID 快照和 200 条页大小流式读取；保留期清理按 400 条 ID 分批删除，避免长事务占用写锁。活动表按空间/资源/操作关联/保留时间建立索引，后台日报按时间窗口在数据库聚合活动动作。

## 验证入口

- `tests/files/activity_contract.rs`：可在升级前版本编译运行的黑盒红测。
- `tests/files/activities.rs`：真实认证 API、事务失败、并发、幂等、权限、账号删除、历史未知、保留期和导出边界。
- 前端 `useWorkspaceActivities` / `workspaceActivityService` 单测：切换资源取消请求、忽略过期响应、分页重试与授权路径。
- `frontend-panel/e2e/teams.spec.ts`：团队上传、重命名、刷新后的列表与详情。

通用审计身份、结果和关联模型的后续演进见 [AsterForge #51](https://github.com/AsterCommunity/AsterForge/issues/51)，不是 Drive 活动表的前置依赖。
