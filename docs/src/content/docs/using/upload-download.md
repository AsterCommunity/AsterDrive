:::tip[这一篇讲什么]
普通用户视角的上传和下载：你不需要分辨底层实现，但出问题时知道先看哪里。管理员向的后端准备见 [存储策略与策略组](/admin/storage-policies/) 和各存储后端教程。
:::

## 上传时先记住这几件事

- 小文件通常会很快完成
- 大文件会自动拆成多段上传
- 上传中断后，能继续就继续
- 继续上传时，回到原文件夹重新选同一个文件
- 可恢复上传也有时效：普通分片通常 24 小时，对象存储直传通常更短

日常使用时，你不用分辨"普通上传""分片上传"还是"对象存储直传"——系统按当前工作空间绑定的策略组和文件大小自动决定路径。

:::tip[上传失败先看策略组]
很多上传问题看起来像"文件传不上去"，实际是当前用户或团队命中的策略组不对。先确认工作空间，再确认策略组，再看具体存储策略。
:::

## Cluster 部署时的上传选择

如果你的站点是多 Primary（cluster profile）部署，上传路径会比单实例少几种：需要把临时状态放在单个节点本地的上传方式，在创建会话时就会被系统拒绝。这不是你的文件有问题，而是部署拓扑的限制——被拒绝时不会产生残留的上传会话或暂存文件，换一种可用路径重新上传即可。

你不需要自己判断当前拒绝属于哪种情况；可用路径仍由策略组和存储策略自动决定。管理员侧的限制清单和原因见 [负载均衡与多实例](/deploy/multi-instance/)。

## 下载文件、文件夹和多选内容

点击文件、文件夹或多选操作里的 `下载` 后，页面会让你选择适合当前浏览器的下载方式：

- **前端代理下载**：由当前页面接收文件流，右下角下载中心会显示进度、速度和剩余时间；适合希望在页面里查看或取消进度的单文件下载
- **下载到文件夹**：选择一个本地目录，把所选文件写进去；下载文件夹或多个项目时会保留相对目录结构，浏览器第一次使用时会询问目录写入权限
- **使用浏览器默认下载**：把单个文件直接交给浏览器处理，保存位置和进度由浏览器自己的下载列表管理
- **代理打包下载 ZIP**：由 AsterDrive 打包并在页面内下载，进度会显示在右下角下载中心
- **使用浏览器下载 ZIP**：由 AsterDrive 打包所选内容，然后直接交给浏览器下载

不同浏览器提供的能力不一样。如果浏览器不支持直接写入本地目录，页面会在管理员允许 ZIP 下载时提示改用 ZIP；管理员关闭 ZIP 打包下载后，相关 ZIP 选项会直接消失，不是页面坏了。单文件的浏览器默认下载仍然可以使用。

右下角是上传和下载共用的传输活动区。收起时只显示摘要，展开后可以查看每个项目的状态；代理下载可以取消，失败项目可以重试，已完成项目可以清理。

:::tip[下载中心和任务中心不是一回事]
右下角下载中心记录当前浏览器正在执行的代理下载或目录下载。`任务中心` 记录服务端执行的在线压缩、在线解压、链接导入等后台任务。选择"使用浏览器默认下载"或"使用浏览器下载 ZIP"后，请到浏览器自己的下载列表查看进度。
:::

## 从链接导入文件

如果你拿到的是一个 HTTP/HTTPS 下载链接，而不是本地文件，可以在文件页面使用 `从链接导入`。AsterDrive 会让服务端去下载这个地址，并把结果导入到当前工作空间的目标文件夹。

适合的场景：

- 服务器到目标站点的网络比你的浏览器更稳定
- 想把一个公开下载地址直接存进 AsterDrive
- 需要把文件导入团队空间，但不想先下载到本地再上传

创建任务时可以填写：

- 来源 URL：必须是 `http://` 或 `https://`
- 文件名：可选；不填时会优先使用服务端响应头或 URL 路径推导
- 目标文件夹：默认是当前文件夹
- 预期 SHA-256：可选；填写后，下载完成时会校验文件哈希，不匹配则任务失败

链接导入会创建后台任务，不会卡住当前页面。到当前工作空间的 `任务中心` 查看进度。

管理员可以限制单文件大小、每个任务的下载速度、并发任务数和请求超时，也可以配置内置下载器和 aria2 引擎的兜底顺序；所有引擎都关闭时，新的链接导入任务会被拒绝。完整配置见 [离线下载](/admin/offline-download/)。

:::tip[不是所有链接都能导入]
为了避免服务端被拿去访问内网或元数据地址，链接导入只支持 HTTP/HTTPS，并会拒绝解析到本机、私网、链路本地、多播、文档保留地址和云厂商元数据地址的主机。当前实现不跟随 HTTP 重定向；如果下载站点返回重定向，换成最终真实下载地址再试。站点如果启用了 aria2 引擎，AsterDrive 仍会先做这些校验，但实际出站连接由管理员部署的 aria2 服务完成。
:::

## 任务中心

当前界面里，最常见会进入 `任务中心` 的操作包括：

- 文件夹打包下载
- 选中一批文件或文件夹后在线压缩
- 对压缩包做在线解压
- 从链接导入文件
- 第一次打开压缩包预览时生成清单
- 清空整个回收站

在 `任务中心` 里，你可以：

- 查看任务当前是排队中、处理中、已完成、已取消还是失败
- 查看创建时间、开始时间和完成时间
- 查看每一步的当前进度和状态说明
- 在任务完成后直接打开结果所在文件夹
- 在失败时重新排队

任务中心同样跟着当前工作空间走。你在团队空间里发起的任务，要到对应团队空间的 `任务中心` 去看。

## 上传失败时，先按这个顺序查

1. 当前工作空间是不是切对了
2. 当前用户或团队绑的是哪一个策略组
3. 命中的存储策略单文件大小上限是否够
4. 反向代理的请求体大小和超时时间是否够
5. 如果走对象存储直传，CORS 配置是否正确
6. 如果走 OneDrive Graph 直传，检查浏览器扩展或公司网络是否拦截了对 Microsoft 的访问
7. 如果走 SFTP，Endpoint、SSH 凭据、基础路径和主机密钥指纹是否正确
8. 如果走远程节点，节点是否启用、当前传输方式是否测试通过、协议能力是否兼容、默认远程存储目标是否已应用
9. 用户或团队配额是不是已经满了
