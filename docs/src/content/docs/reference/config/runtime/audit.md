所属入口：`管理 -> 系统设置 -> 审计日志`。其他分组和生效时机见 [系统设置](/reference/config/runtime/)。

这一组决定后台和关键操作是否留下记录，也可以按动作范围收窄记录集合。

操作范围仅列出会写入 `audit_logs` 的动作；文件创建、编辑、移动、删除等必记业务活动不在该选择器中。升级前配置中的此类选项会在读取时过滤，新写入会拒绝这些不适用的动作，不影响活动记录，也不会扩大其他审计动作的选择范围。

- **`启用审计日志`**
- **`记录的审计操作范围`**
- **`审计日志保留时长`**

:::caution[不建议轻易关闭]
想之后还能追查"谁创建了分享、谁改了团队成员"，建议保持开启。

主节点的服务启动和关闭也会作为审计事件记录下来，分别是 `server_start` 和 `server_shutdown`。
:::

## 文件活动保留期

`文件活动保留天数`（`workspace_activity_retention_days`）控制工作空间文件/目录的业务活动保留期，默认 `0`，表示永久保留。正数表示按天清理过期活动；负数及非整数配置会被拒绝。

必需文件活动与业务修改原子提交，不受 `启用审计日志` 或 `记录的审计操作范围` 影响；上面这两个选项仅控制系统、管理与安全审计。`审计日志保留时长` 不会清理文件活动。清理活动不会删除文件当前的创建者或最后修改者摘要，升级前的旧审计也不会被伪造为新活动。
